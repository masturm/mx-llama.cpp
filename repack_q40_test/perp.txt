A cache is a smaller, faster storage layer that holds copies of the data most likely to be needed next. When the processor wants a value, it first checks the cache; if the value is present, this is a cache hit and the read is fast. If the value is absent, this is a cache miss, and the data must be fetched from the slower main memory. Caches exploit two kinds of locality. Temporal locality means that a recently used item is likely to be used again soon, so keeping it around pays off. Spatial locality means that items near a recently used one are likely to be used next, so fetching a whole block at once helps. The size of the cache, the size of each block, and the replacement policy all affect the hit rate. A small cache misses often because it cannot hold the working set. A large cache costs more silicon and takes longer to search. The replacement policy decides which line to evict on a miss; common choices are least recently used and pseudo-random. Misses cost the most when the memory latency is high, so designers add several levels of cache, each larger and slower than the one before it. Registers sit at the top, then the level one cache, then the level two, and finally the main memory at the bottom. Each level hides the latency of the level below it. A well tuned cache hierarchy can make a slow memory appear nearly as fast as a small register file, which is why virtually every modern processor relies on it.

A well tuned cache hierarchy can make a slow memory appear nearly as fast as a small register file, which is why virtually every modern processor relies on it.
